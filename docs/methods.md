# 理论基础、方法设计与创新边界

本文解释仓库中已经实现的设计及其可验证性。这里的“创新”主要指面向本地研究工作台的工程组合与约束设计，
不意味着发明了 ReAct、Working Set、BM25、RRF、Event Bus 或流式推理，也不代表已获得学术新颖性或性能优势证明。

## 1. 问题与目标

研究任务常同时消耗多种有限资源：模型窗口、Token/API 费用、工具次数和执行时长。
简单 ReAct 循环容易把执行状态藏在控制流中，固定轮数记忆则不能反映长工具输出的实际上下文开销。
本项目将“执行控制”“活动上下文”“可恢复存储”和“可观察事件”分别建模，再通过明确边界连接。

目标是让一次任务可解释、可中断、资源有界，并尽可能恢复已有工作；不是让本地程序宣称能控制供应商的内部生成过程。

## 2. 从固定轮数到 Context Working Set

### 2.1 容量模型

将窗口容量记为 `W`，模型输出预留为 `O`，工具定义为 `T`，消息封装余量为 `F`，
系统/开发者指令与当前任务的必保留内容为 `P`。可分配给历史的预算为：

```text
B_history = W - O - T - F - P
```

组装必须满足 `estimated_tokens(context) + O <= W`。
默认计数器基于 JSON 的 UTF-8 字节数与固定开销，是保守本地估算，不是供应商 tokenizer。
API 返回的真实 Usage 用于执行预算结算，不能倒推这次组装的估算就是精确 Token 数。

分类统计涵盖 system、user task、history、tool definitions、tool results、output reserve 等。
当前 RAG 内容通常处于工具结果中；`rag` 分类接口不代表已经实现独立 RAG 配额求解器。

### 2.2 实际选择策略

`agent/context.py` 当前采用可解释的确定性启发式，而不是训练出来的调度策略：

1. 校验 Tool Call / Tool Result 批次的完整性与唯一标识。
2. 必保留系统指令、当前任务、显式固定约束与 Runtime 状态。
3. 大工具输出保留短前缀预览，完整结果卸载到 SQLite，并在活动上下文中留下恢复引用。
4. 历史按“是否含约束、与当前任务词项的匹配程度、时间顺序”排序，在预算内选择完整轮次。
5. 去重以序列化后的完整轮次为单位；未选中的历史持久化后移出活动内存。
6. 按原时间顺序组装所选历史，发布占用组成与片段溯源事件。

约束检测包含关键词规则，不能保证理解所有自然语言约束。必保留内容超过窗口时明确失败，
不会偷偷截掉系统指令或拆开工具协议来让请求“看起来成功”。

### 2.3 换出与恢复

SQLite 档案按 scope 隔离，保存来源、估算占用、重要度与操作历史。
`recall_context` 可通过查询或引用读取原始信息，并支持有界读取。
档案搜索使用本地全文检索/回退匹配，**没有实现上下文档案的向量索引**；不要与论文知识库的向量检索混为一谈。
压缩方式主要为抽取式前缀预览，不是语义摘要模型。

与虚拟内存的类比是“活动窗口 + 后备存储 + 显式换入换出”，不是操作系统级地址空间透明性。
被换出的信息需要工具恢复，模型未必能主动发现所有需要恢复的材料。

代码与验证：`agent/context.py`、`tools/context_recall.py`、`tests/test_context_engine.py`。

## 3. 多维预算的预留与结算

在请求前预留估算输入与最大输出，避免一个请求在发出前就明显无法满足任务余额。
费用估算采用用户提供的输入/输出单价：

```text
estimated_cost = input_tokens * input_rate / 1e6
               + output_tokens * output_rate / 1e6
```

Usage 可用时，用真实输入/输出数量替换预留；价格仍是配置估算，不是已核验账单。
Usage 缺失、断流或取消时保留未结算预留，防止把“不知道消耗了多少”误记为零。
任务层还限制步数、模型/工具调用次数、时长和恢复次数；接近预算上限时减少后续消耗。

预算与供应商不是原子事务：如果供应商返回的实际用量超过请求预期，本地只能停止之后的调度，
不能追回已发生费用。模型切换也只在已配置的模型档位内进行。

代码与验证：`agent/budget.py`、`agent/runtime.py`、`tests/test_resilience.py`、`tests/test_runtime.py`。

## 4. 流式输出与工具执行的双阶段边界

流式文本可以立即展示；工具调用必须等到完整性确定后才能执行。
协议聚合以调用索引收集 name / arguments，并检查 ID 稳定性与唯一性。

```text
Provider deltas
  ├─ 正文 / 供应商推理 → 聚合与脱敏 → 实时 UI
  └─ 工具参数片段 → 完整 finish → JSON object → schema → 权限 / 确认 → 执行
```

任一工具缺少完整参数、结束原因不合法或批次校验失败，整批不进入工具执行。
Schema 校验只覆盖当前工具使用的子集，不是完整 JSON Schema 标准实现。
出现部分输出后断流时保留内容并终止当前执行，不自动重发导致重复输出或重复副作用。

客户端时间使用 monotonic：

| 指标 | 当前定义 |
| --- | --- |
| TTFT | 首个非空白正文或供应商推理片段 |
| TTFR | 首个非空白供应商推理片段 |
| First visible | 首个非空白正文片段 |
| Response duration | 请求开始至流读取完成 |
| Throughput | API `completion_tokens` / 完整客户端耗时，包含等待阶段 |

空包、角色声明不触发首片段指标。只有工具参数而没有正文/推理时，上述首文本指标不可用。
供应商没有返回的推理或 Usage 不补造；客户端时延不能称为供应商内部推理时延。

代码与验证：`llm/streaming.py`、`agent/core.py`、`tests/test_streaming.py`、`tests/test_streaming_http.py`。

## 5. 控制面与观察面分离

显式状态机负责合法转换；Hook/Middleware 决定是否或如何执行；Event Bus 发布已经发生的事实。
Trace、Inspector、预算统计与 Checkpoint 订阅这些事件，而不是各自反向猜测 ReAct 的控制流。
关键持久化失败会阻断继续调度，普通观察者故障不传播成业务执行故障。

当前工程组合的价值在于约束可互相核对：

- 已取消的任务不能继续派发新工具。
- 未完成的参数不能因 UI 已显示工具名而被提前执行。
- 未返回 Usage 的请求不能在预算面板显示“已知为零”。
- 历史回放不能被当作新执行；新分支必须显式创建并遵守工具副作用限制。

Trace 是执行事件与供应商可见输出记录，不是模型隐含思维的还原。

代码与验证：`agent/runtime.py`、`agent/task.py`、`agent/observability.py`、`agent/debugging.py` 及对应测试。

## 6. 可组合的检索证据

PDF 切分保留页码、片段 ID 和前后关系；检索与相邻片段扩展用于补充局部上下文。
混合检索使用已有的加权 RRF 思路，避免直接比较不同通道的原始分数：

```text
score(document) = Σ_channel weight(channel) / (k + rank_channel(document))
```

向量通道可选，本地哈希通道是轻量近似。当前没有学习通道权重、跨论文证据冲突消解，
也没有证明混合检索在本项目语料上优于 BM25。保留页码能支持引用核查，不自动保证模型引文正确。

代码与验证：`ingest/builder.py`、`retrievers/hybrid.py`、`tools/knowledge.py` 及检索测试。

## 7. 能主张什么，不能主张什么

| 候选贡献 | 当前证据 | 仍缺什么 |
| --- | --- | --- |
| 面向研究 Agent 的预算化 Context Working Set | 实现、溯源事件、卸载恢复测试 | 标准数据集、精确 tokenizer、多任务消融与真实成功率 |
| 预算预留与可中断执行的组合 | 断流/取消/Usage 测试 | 多供应商长任务费用对账与异常压力测试 |
| 流式工具调用的提交边界 | JSON/Schema/取消/并行调用测试 | 更多兼容服务的持续协议测试 |
| 状态、恢复、上下文与 Trace 的低耦合组合 | 事件隔离、持久化与恢复测试 | 并发服务、长时间稳定性及独立用户评估 |

这些可以作为工程设计特点或研究假设，不应写成“原创算法”“达到 SOTA”或“显著提升成功率”。
需要学术创新判断时，还应开展系统相关工作检索；本文不是新颖性检索报告。

## 8. 评估方法

`python scripts/benchmark_context.py` 对比固定轮数 Memory 与动态工作集，使用相同的合成本地对话和大工具输出。
输出口径为估算提示词开销、指定信息是否在活动上下文、是否能从档案恢复，以及本地总耗时。
其中模型任务成功率为 null，因为没有调用模型。保留率只是固定测试信息的二元检查，不是通用质量评分。

运行基准时应保存环境、配置、代码版本与多次采样结果，再开展真实论文任务、人审答案和消融实验。
临时输出写入 `artifacts/`，不将缺少环境信息的历史单次测量作为发布依据。
